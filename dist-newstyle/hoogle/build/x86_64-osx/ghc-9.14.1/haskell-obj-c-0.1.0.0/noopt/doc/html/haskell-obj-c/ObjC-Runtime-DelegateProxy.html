ObjC.Runtime.DelegateProxy

Description

Compose multiple delegate objects into a single ObjC object via message forwarding.

When an ObjC API requires the same object to serve as both delegate and data source (or conform to multiple protocols), this module lets you combine per-protocol delegate objects without Template Haskell.

How It Works

The proxy class overrides forwardingTargetForSelector: — the ObjC runtime calls this before raising doesNotRecognizeSelector: when a message arrives that the proxy doesn't directly implement. The override iterates through the delegate list and returns the first one that responds, causing the runtime to re-dispatch the message to that delegate. No NSInvocation boxing is involved; this is the fast forwarding path.

Usage

dataSource <- newNSTableViewDataSource $ ...
delegate   <- newNSTableViewDelegate $ ...
combined   <- newDelegateProxy [dataSource, delegate]

-- Set combined as both delegate and dataSource on the table view.

When separate objects work fine (most cases), prefer that over a proxy — it's simpler and avoids the extra forwarding hop.

newDelegateProxy :: [RawId] -> IO RawId Source #

Create a proxy that forwards messages to the first delegate that responds to each selector.

The delegates are tried in order, so earlier entries take priority when multiple delegates respond to the same selector.
